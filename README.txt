# 寻归荒野｜公告模块部署包

## 包内文件
- `index.html`：原游戏网页，已加入启动全局公告弹窗。
- `announcement-settings.html`：公告管理界面，包含主开关、浅/深色主题、显示/隐藏图标、预置图标恢复、上传/移除自定义图标、标题/正文编辑、实时预览。
- `assets/announcement.css`、`assets/announcement.js`：公告前端样式与逻辑。
- `assets/favicon.svg`：浏览器标签页图标（自绘几何山形，不依赖字体、不含第三方商标）。
- `assets/notice-icon.jpg`：公告图标（ASCII 文件名，避免部署平台的中文路径问题；旧中文名路径会自动迁移）。
- `assets/music/`：音乐库曲库——`春来`、`发光时代`、`我怀念的`、`野心` 四首 MP3。
- `assets/ambience/`：包内的环境声音。`forest/` 是林间 27 片各自原声的本地备份（80 kbps 立体声，同一条录音转的，合计约 128 MB），联网够不着原处时放它；`sea-layers/` 是"听海"的 15 段原站海层（一段不少，原样未转码，合计约 235 MB），`sea-icons/orig/` 是原站那 15 枚线描小图，`sea-visual/` 是原站用的两张海面贴图。照片只剩一处：`forest-photos/t*.jpg` 26 张（"林间"那 27 片林子各自页面上自己配的那张封面，缩到最长边 1600 存进包内并改名；其中一片林子自己的页面就没有配图）。上一版那 6 张听海图库照片、12 张 Unsplash 林间照片、两张查不出出处的旧全屏头图都已从包里删除；图片 ID 与删除说明都记在 `声音来源.txt`。
- `assets/sea3d.js`：实时 3D 海面。原站那套 Water 着色器 + Mirror 反射 + Sky 天色，水色、日光色、太阳方位、倾角、畸变、反射相机 55° 全按原站常量搬过来；一片水面、九十根木桩，镜头在 15 上下 1.2 的范围内起伏（原站是 ±4.5，铺满整页没有页脚可挡，收窄之后贴图边不会翻出来）。听海出声时铺满整页，暂停收回；手机上按 1.15 倍像素比画，切到后台停帧，系统开了"减少动态效果"时只画一帧静止的海。
- `assets/three/`：three.js r82 本体与镜面、水面、天空三个着色器（`vt/three.min.js`、`Mirror.js`、`WaterShader.js`、`SkyShader-day.js`），MIT 许可；许可全文 `LICENSE.txt` 随包附上。页面不引用任何外部 CDN，离线可用。
- `assets/scene-art/photo/`：59 张实拍照片（WebP，长边 1440、q72，合计 8.5 MB），一幕一张安静地垫在纸面之后——54 幕正传、15 个结局、起始页与封面共用这一批；`assets/scene-art/photo/thumb/` 是同一批的 480px 缩图（1.4 MB），只有起始页的分格背景用。幕与照片的对应关系写在 `index.html` 里三个数据块：`SCENE_ART`（每一幕 → 一张）、`ENDING_ART`（每个结局 → 一张）、`COVER_ART`（封面那一张）。旧的那 13 张水彩插画（`assets/scene-art/*.jpg`）这一轮换下架，文件已删。
- `声音来源.txt`：这一份是包里唯一写来源的文件（不进页面、不进浏览器）。六节——林间 27 段同源本地备份（本地文件名、时长、大小，与叁一一对应）；听海那 15 个声层逐条的原站层名、本产品曲名、包内文件与原处地址；联网时优先去够的 27 条林间录音（含地点原文、录音者、封面原址与包内文件名）；听海 15 枚原站图标与林间 26 张封面的对应；实时海面所用 three.js / 着色器 / 两张贴图的署名；最后是够不着的那部分与实测证据。页面上只显示曲名和地点，不显示任何来源信息。
- `assets/ncm-logo.ico`：音乐库悬浮按钮使用的网易云音乐站点图标（32×32 ICO）。
- `assets/music-player.css`、`assets/music-player.js`：音乐库悬浮组件（页面右上角圆形图标，点击弹出播放面板；四枚页签"音笺 / 听海 / 林间 / 找歌"，两个声音房都能铺满全屏听）。听海 15 层（前三层互斥，其余可叠）、林间 27 片；林间曲目表里的 `remote:` 就是"原处那一条"的地址，27 条都有，删掉这些字段就退回纯包内播放（其余代码一行不用改）。
- `assets/videos/e1.mp4 … e15.mp4`：15 个结局各一条彩蛋视频（ASCII 文件名，避免部署平台的中文路径问题）。
- `assets/ink/paper.webp`：Blender 渲染的无缝纸纤维（512×512，叠在纸面上）。
- `assets/ink/paper-soft.webp`：同一张纤维的淡一档版本（约原来四成的墨），首页正文与卡片用它；音乐库面板仍用 `paper.webp`。
- 顶栏三枚功能件的小图标（玩法 / 档案库 / 存档，17×17，纯几何自绘，不含第三方图形）这次改成内联在 `index.html` 的 CSS 里（三张各不到 0.4KB 的 data URI），不再单独占文件——CSS 的 `mask` 是按 CORS 规则取图的，双击本地文件时浏览器会拒收外部图片，图标就空了；内联之后本地和线上都能画。图没加载上时文字仍在、位置不塌这条保底也保留着。
- `assets/ink/ridge-1.webp … ridge-4.webp`：四幅木刻远山（1600×560），按结局名固定对应，作为结局页的收束。
- `assets/ending-video.css`、`assets/ending-video.js`：结局彩蛋视频弹层（自定义播放控件、自由拉伸、进度任意跳转）。
- `netlify/functions/announcement.mjs`：全站公告的读取/保存接口，使用 Netlify Blobs 持久化。
- `netlify/functions/music-search.mjs`：音乐搜索接口。代理搜索与试听直链解析（聚合公开音源检索结果），不保存任何用户数据。
- `scripts/build.mjs`：构建网页输出目录。
- `package.json`、`netlify.toml`：Netlify Functions 部署配置。
- `404.html`、`robots.txt`：走错地址时的"档案缺页"页；以及禁止搜索引擎收录公告后台的规则。
- `.nojekyll`：空文件，只为 GitHub Pages 准备——有它在，Pages 才会把这些文件按原样发布，不用先过一遍 Jekyll。放在 Netlify 上它没有任何作用，也不影响任何功能。

## 全局同步机制
正式发布并启用函数后，游戏首页每次加载会从 `/.netlify/functions/announcement` 读取全站当前配置。设置页通过管理员口令提交修改，后端将配置写入 Netlify Blobs，其他访客下次进入时看到更新后的公告。自定义小图会压缩为 JPEG data URL，随配置一并保存。

管理员口令不会写进页面或公告配置。服务器端只接受环境变量 `ANNOUNCEMENT_ADMIN_TOKEN` 对应的口令修改请求。

## 发布前必做
1. 将本包内文件上传/合并到现有 Netlify 站点所连接的代码仓库根目录；保留原有游戏事件代码，不要只上传新增的 `assets` 文件夹。
2. 在 Netlify 项目设置里确认站点使用本包根目录构建，`netlify.toml` 会将静态页面构建到 `dist/`，同时打包 `netlify/functions/announcement.mjs` 与 `netlify/functions/music-search.mjs`。请通过连接 Git 仓库的部署或 Netlify CLI 完成带函数的构建发布，单纯拖拽 `dist/` 静态文件不会部署函数。
3. 在 Netlify 项目的环境变量中新增 `ANNOUNCEMENT_ADMIN_TOKEN`，设置为你自己生成的高强度口令；重新部署使变量生效。不要把口令写进 HTML、JS 或公开仓库。
4. 部署后访问 `/announcement-settings.html`。在“管理员口令”栏输入刚设置的口令，编辑内容后点“保存到全站”。成功后状态区域会说明已经同步。

## 未配置后端时
设置页仍可操作和预览，也会尽量把配置保存在当前浏览器；但会明确提示全站接口不可用，此时修改不会同步给其他访客。首页在后端不可用时会退回本机保存值或默认公告。

## 启动画面顺序
首页打开后先独占显示 `assets/splash.jpg`，图片加载完成后强制显示 6 秒；启动期间不会显示其他页面元素，也不能点击跳过、不会显示倒计时。6 秒结束后才显示公告弹窗；点"我知道了，点击进入游戏"关闭公告后，进入的是起始页——一段可以往下翻的册子（顶部一行导航、压在照片上的书卡、六个时段的位置、逐字点亮的书名、这份档案的说明、地名跑马灯与页脚），点其中的"打开档案，开始"（有存档时同一位置写"接着上次那一步"）进第一幕。
两道保险不影响上面的顺序，只防止极端情况：图片请求一直挂着（既不成功也不失败）时，最迟 11 秒强制走完冷启动；公告脚本万一没能运行，启动图结束 9 秒后自动解除整页隐藏，不会再出现"一片空白"的死页面。

## 更早的更新（听海：把照片换成一片真的海）
听海六段的画面从"一张照片 + 叠一层波光"换成一片实时算出来的海：浪的形状、天空的颜色、浪尖的碎光都由这台设备一帧帧算出来，不联网、也不下载图片。声音、曲名、地点、林间的照片和游戏内容一个都没动。

- 引擎是 three.js（r147，MIT 许可）官方示例里的两个着色器对象：`Water`（常说的 Water 2017 平面反射海洋模型）与 `Sky`（Preetham 解析日光模型）。`three.min.js`、`Water.js`、`Sky.js` 全部下载进 `assets/three/`，页面不引用任何外部 CDN——双击本地文件也是同一片海。许可全文随包（`assets/three/LICENSE.txt`），署名只写在包内 `声音来源.txt`，页面上不出现引擎名。
- 六段各有各的海：白日、风暴、午后、阴天、落日、破晓，逐段配了太阳高度角、大气浑浊度、浪高、观察高度、镜头俯角与曝光。风暴那段浪高 9、扰动强度 55，落日与破晓把太阳压到 2 度左右的地平线上，浪尖带一层暖色碎光。海面波形用的法线贴图由程序自己生成（整数频率正弦波叠加，再乘一层同样取整数频率的包络，256×256，四方连续无缝），不含任何第三方图片。
- 会呼吸的地方：镜头像在小船上那样极轻地左右扫、上下伏；全屏时可以拖着转视角（横向 ±0.8 弧度、俯仰 −0.4~+0.5，松手慢慢回位），轻轻点一下（位移小于 9px）浪会短暂大起来——扰动抬到 1.4 倍，2.6 秒里自己平复回去。房卡里特意不做拖拽：手机上想往上滑，不该被画面抓住。
- 颜色这一轮是量出来的，不是调出来的。改之前房卡水面色带实测平均 RGB (157,161,161)、饱和度 0.049，接近灰色——两个原因叠在一起：ACES 色调映射把高光的青蓝压成灰白，音乐库那层绿色纱又罩在蓝色海面上。改成线性色调映射、曝光 0.42~0.62，并让纱的颜色跟着画面切换（听海用深蓝纱 `8,17,22`，林间仍是原来的绿纱 `19,29,23`，两档纱的每一层 alpha 逐字节相同）。换完把压在画面上的字逐处重量了一遍——量的不是估计：把那行字临时设成透明，只留下它真正垫着的那层颜色再算比值。结果实时海面的上半是亮天光（照片那版没这么亮），房卡左上角那块名字牌子底只有 .44 压不住：曲名 4.25:1、地点 3.23:1，低于 4.5:1 的线。只把海面上这块牌子的底垫到 .74（曲名回到 10.38:1、地点 6.94:1，牌子左边那道竖线也顺手换成海里的青色），林间那一档一位没动；全屏 7 处最低 6.70:1，无需改。改后实测：房卡水面 (43,58,66)、饱和 0.443；全屏 (27,41,49)、饱和 0.516。
- 退路留了三条：浏览器没有 WebGL 就退回原来那 6 张海面照片；系统开了"减少动态效果"就只画一帧静画；连 3D 模块本身没加载上，也只走同一条回退，不会黑屏或破图。WebGL 上下文意外丢失（驱动休眠、标签页被回收）时也自动回到照片并继续播。
- 性能：绘制锁在 30fps；像素密度上限全屏 1.2、房卡 1.5；页面切到后台自动停笔，回来自动续上；帧时间一旦超过阈值就自动降一档（`lowerQuality`）。房卡与全屏各自一个实例，全屏开着时只更新全屏。WebGL 上下文一共两个——房卡一块画布、全屏一块画布，切房间、关面板、切页签都不会再多开；页面加载时另外探一次"这台设备有没有 WebGL"，探完立刻释放，而且这一趟只探一次（早期版本因为"支持"的返回值是空字符串，每回建海面都重探一遍，一趟下来要占三次，已经改掉了）。

## 更早的更新（看得清、找得到、三种屏都站得住）
这一轮先把"读"这件事量了一遍，再把两样最容易找不着的东西搬到眼睛会经过的地方，最后拿手机、平板、电脑三种尺寸各自过一遍。游戏内容照旧一个字没动。

- 先把依据摆出来（personality-database 对 这一型 的原文，四条量过之后才动界面）。"感受很深却很少表达，柔软与确信都被表面的沉静盖住"——入口不该需要人去找，更不该需要人去问；"尤其内敛、害羞"配上大五低外向——这样的人不会满页找按钮，玩法与存档若藏在页边一枚 32px 的竖条里，就等于没有（实测那两枚竖条在 390px 上还直接压在正文上）；Te 压力下"会不断想着别人怎么批评自己"——一页要眯眼才读得清的字，读起来像被嫌弃。判据仍是那一条：一个不喜欢被打分、对光线和声音敏感的人，深夜一个人打开这页，会不会觉得安心。

## 更早的更新（落墨：让纸有纤维，让结尾有远山）
这一轮不再加功能，只把"纸"和"墨"两件事做实。素材是用 Blender 4.5.3 LTS 无头渲染的，不是滤镜叠出来的。

- 结局页最后多了一幅木刻远山（1600×560，四幅一套，与封面底部那幅遥遥相对）。它按结局标题的字符和固定取模选图：同一个结局每次回来看到的是同一片山，不会随机跳。图放在两个按钮之后，隔一道细线，底部用遮罩淡出；图没加载完就保持空白（`opacity:0`），绝不出现破图图标，也不占位跳动。深色主题下反相压到 30%，夜里不刺眼。它不是一打开就亮：要等图和"人真的滚到这里"两件事都发生，才淡进来；封面停留时用 `requestIdleCallback` 预取四幅图，进结局不用等。
- 封面上那三块小字（快捷键提示、图鉴说明、隐私说明）原来各有一个浅色底框，像三枚标签贴在封面上。现在去掉了底、框和阴影，收成一段安静的落款：一条细线在上，其余靠行距分开。对比度实测浅色 4.83:1、深色 6.45:1，没有为了好看牺牲可读性。那行"档案库"看起来仍是一行小字，但手指按得到的地方有 44px 高（用不吃布局的伪元素撑开，字和细线的位置没动）。

- 卡片和结果页多了一层纸的厚度：3px 与 6px 两级错位的同色纸边，加一道很淡的投影，看起来像两张纸叠着，不是浮在空中的卡片。只改 `box-shadow`，边框盒与点击区域一寸没动；390px 与 1280px 下页面横向溢出均为 0。

## 音乐库"歌曲搜索"标签（联网试听）
面板顶部为双标签：默认打开"收藏曲库"，原四首歌曲与试听行为完全不变；第二个"歌曲搜索"标签可以联网搜索歌名或歌手并在线试听。

本包采用了"双通道"设计：部署了函数的站点优先走自带的 `netlify/functions/music-search.mjs`；没有函数的部署方式（包括本地打开、Netlify 拖拽上传）会自动回退到 GD Studio 公开聚合接口（https://music-api.gdstudio.xyz，来源为网易云音乐）。因此把 zip 拖上 Netlify 也能完整联网搜索与试听，无需任何 API 密钥。

使用限制：
- 公开接口属于第三方免费服务，可用性不在我方可控范围；若某天接口失效，场景表现为"搜索服务暂不可用"或部分歌曲提示"该曲目暂时无法播放"（VIP / 无授权歌曲没有试听直链）。
- 在搜索结果右侧点红心即可把歌加入收藏；收藏曲库里网络歌的条目带删除红心，点按可移出收藏。收藏保存在当前浏览器（最多 20 首），下次进入自动恢复；换浏览器、换设备不会同步。

## 拖拽部署（最简方式，本包推荐给不会用 Git 的用户）
1. 打开 https://app.netlify.com/drop （保持 Netlify 登录状态）；
2. 把本 zip 直接拖到页面中央的大区域，等待上传与发布完成；
3. 新站点默认公开访问，无人需要登录即可打开。**不要使用通过其它工具创建的受密码保护 / 草稿站点**；
4. 打开发布后的网址，网页面板与音乐库立即全部可用。
注意：拖拽部署只发布静态文件，公告的"一键全站同步"接口不会生效——首页会显示内置的默认公告（标题"温馨提醒"、完整正文、自带图标照片）。如果需要全站同步公告（访客共同看到你改的内容），请改用 GitHub + 连接仓库的部署方式（见"发布前必做"），配置步骤相同。

## 放到 GitHub Pages（想用 GitHub 发布时看这一节）
这个包的根目录就是 GitHub Pages 要发布的那一层：`index.html` 在最外层，页面里的资源全部写成相对路径（`./assets/…`），所以放在 `https://用户名.github.io/仓库名/` 这种子路径下也能正常打开。包根目录还带了一个空的 `.nojekyll`：GitHub Pages 默认会先跑一遍 Jekyll 再发布，有这个文件就按原样发，少一类意外。

先说两个硬限制（2026 年 10 月核对的 GitHub 官方文档）：通过网页界面「Add file」上传，单个文件不能超过 25 MiB——本包 260 个文件里，`assets/ambience/sea-layers/rowing.mp3` 约 71.5 MiB、`assets/videos/e9.mp4` 约 36.9 MiB，都超过这条线，用网页拖会直接失败；用 Git 客户端推送，单个文件上限 100 MiB（超过 50 MiB 会给一条警告，仍能推）。所以走 GitHub 请用桌面客户端，不要用网页拖文件。

1. 注册 / 登录 GitHub，右上角「+」→ New repository，名字随意（例如 `xungui`），选 **Public**（免费账号的 Pages 只对公开仓库开放），不要勾选初始化 README；
2. 安装 GitHub Desktop（桌面客户端，图形界面，不需要命令行），登录后 File → Clone repository，选刚建的那个仓库，选一个本地文件夹；
3. 把本 zip **解压**，把解压出来的所有内容（`index.html`、`assets`、`netlify`、`404.html`、`.nojekyll` 等，是这些文件本身，不是外面那层文件夹）复制进刚克隆下来的仓库文件夹；
4. 回到 GitHub Desktop：左下角写一句提交说明（例如「林间同源备份」），点 Commit to main，再点右上角 Push origin。约 557 MB 要传一会儿，等它显示完成；
5. 打开仓库网页 → Settings → 左侧 Pages → Source 选「Deploy from a branch」→ Branch 选 `main`、目录选 `/ (root)` → Save；
6. 等一两分钟刷新该页面，顶部会出现 `https://用户名.github.io/仓库名/`，那就是公开网址。以后改版只需重复第 3–4 步（覆盖文件 → 提交 → 推送），网址不变。

在 GitHub Pages 上会失效的只有两件事，都不影响玩：公告的「一键全站同步」后台（Pages 不跑服务器函数，首页会退回内置的默认公告，和你现在拖 Netlify Drop 的结果一样）；音乐库的「歌曲搜索」会走公开接口回退，仍然能搜能听。另外免费账号的 Pages 站点上限 1 GB、每月约 100 GB 流量，本包约 557 MB，够用。国内访问 `github.io` 有时会慢或打不开，如果只是想要一个「谁都能打开」的网址，拖 Netlify Drop 仍是最省事的那条路；想两者都要，可以把 Netlify 连到这个 GitHub 仓库，函数会跟着一起部署（见「发布前必做」）。
